# Advanced APK App Cloner

A real, working pipeline that takes an existing APK and produces an independently
installable clone with your chosen customizations — package ID, app name, version,
icon, permissions, and components. It does **not** require the original source
project. It uses the actual Android tools (`apktool`, `zipalign`, `apksigner`,
`aapt`, `keytool`) under the hood, and it will never report a clone as successful
unless every stage genuinely completed and re-verified.

## What's real here (and what isn't)

This tool is built around actual decompile/recompile/re-sign tooling, not a mock:

| Stage | Real implementation |
|---|---|
| Analysis | `androguard` static parsing of the manifest/DEX/resources — no execution of any code from the APK |
| Decode/Rebuild | `apktool` (the standard open-source APK decompiler) |
| Package/version/label/permission/component edits | XML edits to the decoded manifest via `ElementTree` |
| Icon replacement | Real image validation + per-density resize via Pillow |
| Alignment | `zipalign` |
| Signing | `apksigner` with a keystore generated by `keytool` |
| Final validation | Independent re-parse + `apksigner verify` + `zipalign -c`, not just "did the previous step exit 0" |

Honest limitations (by design, not oversight — see spec item 30):
- **No decompiled code renaming.** We rename the package at the manifest level
  and rewrite provider authorities that literally contain the old package
  string. We do **not** rewrite Java/Kotlin logic inside the DEX, so an app
  that hard-codes its own package name in code may partially break after a
  package rename. This is flagged as a warning in every such clone.
- **Split/Configuration APKs** are detected and flagged as `HIGH RISK` rather
  than silently mis-cloned.
- **Obfuscated apps** are flagged; internal references may not fully resolve.
- **Installed-app auto-discovery** (`platforms/android.py`) calls the real
  Android `pm` command. In any environment where `pm` isn't available (like a
  desktop dev sandbox, or a Termux install without the right permissions) it
  says so plainly and points you to manual APK selection — it never invents a
  fake app list.
- **On-device install testing** requires an actual ADB-connected device. If
  none is present, the tool reports "installation test skipped" — it never
  claims an install happened without one.
- We do **not** bypass DRM, signature verification, Play Integrity, or any
  other anti-tampering mechanism, and we won't build features to do so. This
  tool is for APKs you're authorized to modify (e.g. rebranding/cloning your
  own apps, or apps you have explicit permission to alter).

## Requirements

```
apt-get install -y openjdk-21-jdk-headless apktool zipalign apksigner aapt
pip3 install --break-system-packages androguard Pillow rich
```

The tool checks all of this itself on startup (`ENVIRONMENT CHECK`) and tells
you exactly what's missing and how to install it — it never assumes.

## Usage

```
python3 main.py            # interactive CLI
python3 main.py --debug    # same, but with full tracebacks on unexpected errors
```

Flow: pick a mode (installed apps / manual APK path / history) → the tool
analyzes the APK and shows a cloneability report → you customize what's
supported → it decodes, edits, rebuilds, aligns, signs, and independently
re-validates the result → only then does it save the APK and print
`Clone successful ✓`.

## Project layout

```
apk-cloner/
├── main.py
├── cli/            menu.py, prompts.py, display.py (rich-based UI)
├── core/           analyzer, modifier, builder, aligner, signer, validator,
│                   manifest/resource/component/permission managers, clone_engine
├── platforms/      android.py (pm-based install discovery), windows.py, detection.py
├── storage/        history.py, config.py, workspace.py (isolated temp dirs)
├── security/       keystore.py, secrets.py (path/zip-slip protection, redaction)
├── tools/          tool_manager.py (dependency detection)
└── tests/          pytest suite (builds its own minimal legit test APK — no
                    external downloads)
```

## Testing

```
pip3 install --break-system-packages pytest
python3 -m pytest tests/ -v
```

The test suite builds its own tiny, legally clean fixture APK at test time
(using `aapt` and a hand-built minimal DEX) rather than depending on any
external/downloaded APK, then runs the **full real pipeline** against it —
decode, package rename, version bump, permission removal, rebuild, align,
sign — and independently re-verifies the output with `apksigner verify` and
`aapt dump badging` outside of the tool's own code.

## Security notes

- The original APK is copied into an isolated temp workspace and hashed before
  and after the run; the pipeline refuses to report success if that hash ever
  changes.
- Signing passwords are generated in-memory, passed to subprocesses via argv,
  and never written to logs, `clone-info.json`, or history.
- All zip extraction is protected against path traversal (zip-slip).
- No file from the input APK is ever executed.

## Known gaps for a future pass

- `resource_manager.set_string_value` only edits `res/values/strings.xml`
  directly; a resource *browser* UI (spec §6) exists via `ResourceManager.search`
  but isn't wired into the CLI menu yet.
- ADB-based install-on-PC and on-device install flows are stubbed to detect
  `adb` and report status honestly, but don't yet drive an actual `adb install`
  call.
- Multi-APK/split-APK "process complete set" mode (spec §23) currently only
  detects and warns; it doesn't yet merge split APKs into one.
